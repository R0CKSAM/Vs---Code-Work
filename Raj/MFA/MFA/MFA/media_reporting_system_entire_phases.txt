MEDIA REPORTING SYSTEM
COMPLETE DEVELOPMENT PHASE PLAN

PROJECT GOAL
Build a professional Media Reporting System that monitors media websites,
collects news and advertisement information, detects changes, maintains
history, and produces daily/weekly/custom reports.

INITIAL MONITORED WEBSITES
1. ET BrandEquity
   https://brandequity.economictimes.indiatimes.com/
2. Exchange4media
   https://www.exchange4media.com/

The system should eventually support approximately 10 media websites.

IMPORTANT DEVELOPMENT PRINCIPLES
- Build incrementally.
- Complete and verify one phase before starting the next.
- Keep early versions local and free/open-source.
- Do not introduce Docker, Redis, Celery, cloud infrastructure, or other
  heavy infrastructure until the local application is already working.
- Do not use paid APIs unless explicitly approved later.
- Use system Python; do not create a Python virtual environment.
- Keep the UI professional and suitable for non-technical users.
- Preserve historical monitoring data.
- Respect robots.txt, website terms, reasonable request rates, and applicable law.
- Do not automatically bypass anti-bot or access restrictions.

RECOMMENDED STACK
- Frontend: React + TypeScript + Vite
- Backend: Python + FastAPI + Pydantic
- Scraping: Requests + BeautifulSoup; Playwright later if required
- Scheduling: APScheduler initially
- Database: PostgreSQL later
- Storage: Local filesystem initially
- Reporting: PDF + Excel
- Charts: Recharts or another lightweight chart library

PHASE 5 — CHANGE DETECTION
============================================================

OBJECTIVE
Detect new, updated, unchanged, and removed content.

STATUSES
- NEW
- UPDATED
- UNCHANGED
- REMOVED

Use:
- Stable article URL/identity
- Content hash
- First seen
- Last seen

Example:
First scrape: Article A = NEW
Second scrape: same URL + same hash = UNCHANGED
Third scrape: same URL + changed hash = UPDATED

If an article previously existed but disappears from a monitored page,
treat it according to defined monitoring rules. Do not delete history.

CREATE CHANGE LOG RECORDS
- Website
- Item type
- Item ID
- Change type
- Timestamp
- Previous value where appropriate
- New value where appropriate

============================================================
PHASE 9 — AUTOMATION
============================================================

OBJECTIVE
Run monitoring automatically every 10 minutes.

INITIAL SCHEDULER
APScheduler

WORKFLOW
Every 10 minutes:
1. Start monitoring run
2. Scrape ET BrandEquity
3. Save/update articles
4. Detect article changes
5. Monitor advertisements
6. Scrape Exchange4media
7. Save/update articles
8. Detect changes
9. Monitor advertisements
10. Record scrape run
11. Update dashboard
12. Store errors/logs

IMPORTANT
- Avoid overlapping runs
- Record duration
- Record failures
- Continue monitoring other sites if one site fails
- Use reasonable request delays
- Respect robots.txt and website terms

SYSTEM SCRAPER STATUS
- Last run
- Current status
- Duration
- Items found
- Error count
- Next run

COMPLETION
- Automatic 10-minute monitoring works locally
- Failures are recorded
- Dashboard reflects monitoring state
