# Smart Flow v20.4.0 — audit and verification

## Reported failure and fix

The user's updated 1.1 workbook imports all 110 scenes. A new regression reproduced Start remaining disabled immediately after upload because `refresh()` ran before clearing `importBusy`. Clearing the lock followed by a final refresh fixes it. A real installed-extension test imports the workbook through Chrome's file input, clicks Start, and verifies that the submitted first prompt contains the exact 3D-anime style and inward hall-entry instructions.

## Functional changes

Connection checks report the actual content-script version and composer readiness. Missing/stale scripts prompt the user to refresh ChatGPT without losing the queue. Errors persist through popup refresh and scroll into view. Diagnostics use the current manifest version and include queue mode.

Frame selection moved out of Advanced onto the main screen. Its imported position is validated and has an actual-label preview. Selection is blocked during work/generation, checks queue identity and tab ownership, and clears only an exact known pending queue draft. Files and history remain intact. Start and Resume respect the selected position.

Prompt recovery is limited to unsent prepared prompts with stable user-message evidence. An identical earlier Next message does not count as the current submission. Other drafts, new output or conversation changes block blind repasting. Restore attempts have a limit of three. The queue tolerates a brief missing composer; a persistently disabled Send reports a useful error. Both textarea and rich-text composer insertion/recovery are tested.

With autosave enabled, storyboard and repeat modes wait for Chrome's download completion. Download errors retain the frame and pause. Resume retries saving the existing output; it does not resend the prompt. Existing filenames retain `conflictAction: 'uniquify'`. Pending frames check the original tab and conversation path. A disabled autosave setting retains manual storyboard progression.

## Interface checks and fixes

The Start/Pause/Resume/Stop controls stay visible at the bottom of the scrollable popup. Import success details collapse; next-step guidance explains Ready, Running, Paused, Saving and Done states. Progress count and percentage have separate alignment. Repeat inputs use the same light form treatment as other settings. The main frame picker has a label, valid range and live preview. No duplicate control IDs or horizontal overflow were observed with all sections expanded at the 370-pixel popup width.

Screenshots of Ready, Complete and expanded sections were captured from the actual installed popup and visually inspected. A stale 110-frame import notice left over after preparing a repeat run was found in that inspection and cleared when switching modes.
